## Board Mutation Hook Fix - StateStore Desenkronizasyon Çözümü

### Problem
StateStore'daki board önbelleği (`_board_names`, `_board_rotations`) `Player.board.grid`'den bağımsız yaşıyordu. `Board.place()` ve `Board.remove()` çağrıldığında StateStore otomatik güncellenmiyordu, bu da UI'ın bazen gerçek board durumundan farklı bir snapshot göstermesine neden oluyordu.

### Çözüm
Board önbelleği zaten kaldırılmıştı (H3-5), ancak `Board._mutation_callback` mekanizması GameState'e bağlı değildi. Bu sorunu çözdük:

1. **GameState.hook_engine()** içine `_attach_board_mutation_callbacks()` eklendi
2. Her oyuncunun board'una mutation callback atandı
3. Callback `board_mutated` sinyalini emit ediyor
4. Sinyal cache invalidation tetikliyor
5. Cleanup mekanizması memory leak'leri önlüyor

### Uygulama Detayları

**v2/core/game_state.py:**
```python
def _attach_board_mutation_callbacks(self):
    """Hook Board._mutation_callback to invalidate cache on direct board mutations."""
    for player in game.players:
        board = getattr(player, "board", None)
        if board is not None:
            board._mutation_callback = lambda pid=player.pid: self._on_direct_board_mutation(pid)

def _on_direct_board_mutation(self, pid: int):
    """Handle direct board mutations - emits board_mutated signal."""
    game.signals.board_mutated.emit(pid=pid)
```

### Avantajlar
- **Garantili Senkronizasyon**: Board mutasyonları her zaman cache invalidation tetikler
- **Sinyal Bazlı Mimari**: Mevcut sinyal sistemine entegre
- **Player-Specific Invalidation**: Sadece ilgili oyuncunun cache'i invalidate edilir
- **Memory Leak Koruması**: Cleanup mekanizması ile callback'ler temizlenir
- **Backward Compatible**: Mevcut kod değişmeden çalışmaya devam eder

### Performans
