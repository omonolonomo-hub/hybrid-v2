# Daily Log - 2026-04-26

## Critical Memory Leaks Fixed (2/2)

### Issue 1: GameState Signal Circular Reference ✅
Identified and fixed a critical memory leak in GameState caused by circular reference through signal observers.

**The Problem:**
- GameState → EngineAdapter → Game → SignalBus → bound method observers → GameState
- Python's reference counting couldn't break the cycle
- `__del__` fallback was unreliable and could cause gc.garbage accumulation
- Every game restart leaked entire game state (30+ cards, all player data)

**The Solution:**
1. Removed `__del__` from GameState (v2/core/game_state.py)
2. Verified ShopScene.on_exit() calls cleanup() deterministically
3. SceneManager properly calls on_exit() during scene transitions
4. Made cleanup() idempotent with clear documentation

**Files Modified:**
- `v2/core/game_state.py` - Removed __del__, improved cleanup() docs
- `docs/MEMORY_LEAK_FIX.md` - Created comprehensive documentation

### Issue 2: SynergyCalculator Class-Level Singleton Cache ✅
Identified and fixed a second critical memory leak caused by class-level cache in SynergyCalculator.

**The Problem:**
- `_last_board_hash` and `_cached_result` were class variables (shared across all instances)
- Old `SynergyComputeResult` with adjacency_pairs persisted after GameState destruction
- Data race risk: multiple GameState instances would overwrite each other's cache
- Test isolation broken: tests interfered with each other

**The Solution:**
1. Converted SynergyCalculator to use instance-level caching
2. Added `__init__` method to initialize instance variables
3. Converted all `@classmethod` decorators to instance methods
4. UIAdapter now creates and holds a SynergyCalculator instance
5. Updated all tests to use instance-level caching
6. Added test for instance isolation

**Files Modified:**
- `v2/core/synergy_calculator.py` - Converted to instance-level caching
- `v2/core/ui_adapter.py` - Added __init__ with SynergyCalculator instance
- `tests/test_synergy_cache.py` - Updated tests, added instance isolation test
- `tests/conftest.py` - Removed class-level cache invalidation
- `docs/SYNERGY_CALCULATOR_MEMORY_LEAK_FIX.md` - Created comprehensive documentation

**Combined Impact:**
- Deterministic cleanup on every scene transition
- Immediate memory reclamation (no GC delay)
- No risk of gc.garbage accumulation
- Memory stable across multiple game restarts
- Thread-safe for parallel simulations
- Test isolation restored

**Test Results:**

### Technical Details

**Issue 1 - Circular Reference:**
The circular reference was created by bound methods in signal observers. When GameState connected to engine signals (board_mutated, economy_changed, etc.), the bound method `_invalidate_cache` held a strong reference back to the GameState instance. This prevented Python's reference counting from collecting the object.

The fix ensures that `_detach_engine_signals()` is called deterministically through the scene lifecycle (on_exit → cleanup → _detach_engine_signals), breaking the circular reference immediately when the scene is destroyed.

**Issue 2 - Class-Level Cache:**
Class variables in Python are shared across all instances of the class. This meant that every UIAdapter (and thus every GameState) was sharing the same SynergyCalculator cache. When a GameState was destroyed, the cache remained in memory, holding references to old card objects and board state.

The fix converts the cache to instance-level, so each UIAdapter has its own SynergyCalculator with its own cache. When the GameState is destroyed, the entire chain (GameState → UIAdapter → SynergyCalculator → cache) is garbage collected immediately.

### Cleanup Chain

```
User exits scene
    ↓
SceneManager.on_exit()
    ↓
ShopScene.on_exit()
    ↓
GameState.cleanup()
    ↓
├─ _detach_engine_signals() [breaks circular reference]
├─ _cached_public_state = None
└─ _adapter = None
    ↓
GameState becomes garbage collectable
    ↓
UIAdapter becomes garbage collectable
    ↓
SynergyCalculator becomes garbage collectable
    ↓
_cached_result becomes garbage collectable
    ↓
All card references freed ✅
```

## Lessons Learned
1. **Avoid __del__ for cleanup** - It's unreliable and can cause GC issues
2. **Use explicit lifecycle methods** - on_enter/on_exit pattern is much cleaner
3. **Signal observers need careful management** - Bound methods create strong references
4. **Avoid class-level mutable state** - Use instance variables for caching
5. **Test isolation matters** - Class-level state breaks test independence
6. **Document cleanup contracts** - Make it clear who owns cleanup responsibility
7. **Always consider parallel execution** - Class-level state creates data races


## HexGridConfig Reset Eksikliği Düzeltildi ✅

### Problem
`HexGridConfig._DEFAULT_CONFIG` singleton pattern kullanıyordu ancak `CardPool`'un aksine `reset()` metodu yoktu. Bu üç soruna yol açıyordu:

1. **Test isolation sorunu:** Aynı process içinde farklı `BOARD_RADIUS` değerleriyle test yazmak imkânsızdı
2. **Frozen binding sorunu:** `ShopScene._drop_dragged_card` ve `MinimapHUD._draw_hex_grid` içindeki `from v2.ui.hex_grid import VALID_HEX_COORDS` import'u, çağrı anında frozenset'i bağlıyordu
3. **Dinamik config desteği bozuktu:** `HexGridConfig.from_custom()` ile farklı config oluşturulsa bile, eski import'lar bunu görmüyordu

### Çözüm

**1. `hex_grid_config.py` - Reset Fonksiyonu Eklendi:**
```python
def reset_default_config() -> None:
    """Reset the default configuration singleton for test isolation."""
    global _DEFAULT_CONFIG
    _DEFAULT_CONFIG = None
```

**2. `ShopScene` - Instance-Based Config:**
- `__init__` içinde `self._hex_config = HexGridConfig.from_engine()` eklendi
- `_drop_dragged_card` içindeki lazy import kaldırıldı
- `coord in self._hex_config.valid_coords` kullanımına geçildi

**3. `MinimapHUD` - Instance-Based Config:**
- `__init__` içinde `self._hex_config = HexGridConfig.from_engine()` eklendi
- `_draw_hex_grid` içindeki lazy import kaldırıldı
- `for q, r in self._hex_config.valid_coords` kullanımına geçildi
