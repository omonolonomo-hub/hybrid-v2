# 2026-04-26 Daily Log

## Performance Fix: Lazy Import Elimination in Hot Render Path

### Problem Identified
Found critical performance leak in drag-and-drop rendering:
- **Location**: `v2/ui/hex_grid.py` and `v2/ui/card_flip.py`
- **Issue**: Lazy imports inside hot render functions causing 180+ `sys.modules` dict lookups per second during 60fps drag operations
- **Impact**: Per-frame overhead on every drag frame

### Specific Violations
1. **hex_grid.py::render_synergy_preview()**:
   - `from v2.core.card_database import CardDatabase`
   - `from v2.core.exceptions import AutochessException`
   - `from v2.constants import ENGINE_HEX_DIRS, OPP_DIR, STAT_TO_GROUP`

2. **hex_grid.py::render_ghost_preview()**:
   - `from v2.core.card_database import CardDatabase`
   - `from v2.ui import font_cache`

3. **card_flip.py::MockCardBox.render()**:
   - `import math` (worst offender - triggered on every empty slot render)

### Solution Applied
Moved all lazy imports to module-level imports at file top:
- **hex_grid.py**: Added `CardDatabase`, `AutochessException`, `font_cache`, `OPP_DIR`, `STAT_TO_GROUP`, and `Any` type hint to top-level imports
- **card_flip.py**: Added `math` to top-level imports

### Performance Impact
- **Before**: 180 dict lookups/second (60fps × 3 lazy imports in drag path)
- **After**: Zero per-frame import overhead
- **Result**: Cleaner hot path, follows Python best practices

### Verification
- No diagnostics errors in either file
- All imports properly organized at module level
- Code follows standard Python import conventions

---

**Lesson**: Always profile hot paths. Lazy imports are convenient but deadly in render loops. Module-level imports are cached once and have zero per-call overhead.


## Performance Fix: Text Surface Allocation Cache

### Problem Identified
Found per-frame static text surface allocation leak in shop scene:
- **Location**: `v2/scenes/shop.py::_render_copy_labels()`
- **Issue**: Every frame creates ~16 new pygame.Surface objects for static "Copies: X/3" text labels
- **Breakdown**: 
  - 5 shop card labels
  - 6 hand card labels
  - Additional tier probability labels in shop_panel
- **Impact**: Continuous GC pressure from small Surface allocations

### Root Cause
The `font_cache.render_text()` helper calls `font.render()` internally, which creates a new Surface every time. These labels only change when:
- Card names change (shop refresh, hand updates)
- Copy counts change (buying/selling cards)

### Solution Applied
Implemented text surface cache with smart invalidation:

1. **Added cache dictionary** in `ShopScene.__init__()`:
   ```python
   self._copy_label_cache: dict[tuple[str, int], pygame.Surface] = {}
   ```

2. **Cache invalidation** in `sync_view()`:
   - Clears cache when card names or state changes
   - Triggered on shop refresh, hand updates, phase changes

3. **Refactored `_render_copy_labels()`**:
   - Cache key: `(card_name, copy_count)`
   - Check cache before rendering
   - Render to cache on miss
   - Blit cached surface directly

### Performance Impact
- **Before**: ~16 Surface allocations per frame (960/second at 60fps)
- **After**: ~16 Surface allocations only on state change (typically <1/second)
- **Result**: 99%+ reduction in text Surface allocations, reduced GC pressure

### Code Pattern
```python
cache_key = (name, count)
if cache_key not in self._copy_label_cache:
    text = f"Copies: {count}/3"
    color = Colors.GOLD_TEXT if count >= 3 else (200, 205, 230)
    self._copy_label_cache[cache_key] = font.render(text, True, color)

text_surf = self._copy_label_cache[cache_key]
surface.blit(text_surf, (x, y))
```

### Verification
- Cache properly initialized in `__init__()`
- Cache cleared in `sync_view()` when state changes
- Direct blitting replaces `font_cache.render_text()` calls

---

**Lesson**: Static UI text should never be re-rendered every frame. Cache rendered surfaces and invalidate only when content changes. This pattern applies to any unchanging visual element in a render loop.
